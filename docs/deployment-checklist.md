# Deployment checklist: Base Sepolia pilot

This checklist takes a clean checkout to a verified Base Sepolia pilot deployment and the first two-device trade. It does not cover mainnet or real funds.

## 0. Preconditions

- Node.js 24+, npm, and a terminal.
- Network access to npm and a Base Sepolia RPC.
- A fresh deployer wallet generated by `pilot prepare`. Never use a mainnet-funded wallet for this role.
- A small amount of Base Sepolia ETH for gas. At typical L2 gas prices, three deployments cost about 0.00003 ETH; 0.0001 ETH leaves room for gas-price movement.
- Two physical devices for the first trade. A local two-process rehearsal is useful, but it does not prove cross-device or public-chain behavior.
- Explicit agreement that the evaluator is offline by default and that review silence pays the provider while arbitration timeout refunds the buyer.

## 1. Build and test

```sh
npm ci
npm run preview:verify
```

Expected: contract compilation, the core test suite, the full Skill demo, and Skill packaging all succeed.

## 2. Generate the deployer identities

Choose a new directory for this pilot. Never reuse a directory from another chain or another build.

```sh
node skills/p2p-orders/scripts/pilot.mjs prepare --out <pilot directory>
node skills/p2p-orders/scripts/pilot.mjs doctor --config <pilot directory>/deployer-wallet.json --state-dir <pilot directory>/deployer-state
```

Record the deployer address, evaluator address, and `preparation.json`. The deployer and evaluator wallets stay local and are never distributed.

## 3. Fund only the deployer

Send Base Sepolia ETH to the deployer address from an official faucet or a trusted developer. Do not buy test ETH and do not send mainnet assets.

Re-run `doctor` until `test-gas` is acceptable:

```sh
node skills/p2p-orders/scripts/pilot.mjs doctor --config <pilot directory>/deployer-wallet.json --state-dir <pilot directory>/deployer-state
```

## 4. Deploy

```sh
node skills/p2p-orders/scripts/pilot.mjs deploy --wallet <pilot directory>/deployer-wallet.json --out <pilot directory>/public
```

Expected: three contract receipts (`deploy_token`, `deploy_orders`, `deploy_payloads`), `<pilot directory>/public/deployment.json`, and a fingerprint. The manifest contains no private keys.

If the process is interrupted, keep the same wallet, directory, and build. Run `deploy` again; the action journal recovers before sending. Never switch wallets, directories, or builds, and never manually resend a deployment transaction.

## 5. Verify the deployment

```sh
node skills/p2p-orders/scripts/pilot.mjs verify --deployment <pilot directory>/public/deployment.json
```

Expected: `ready: true`, and every check passes:

- manifest fields and fingerprint;
- chain ID and deployment block hash;
- confirmation depth;
- runtime code hashes for all three contracts;
- `OrderNetwork.paymentToken()` matches the manifest;
- EIP-712 domain name, version, chain ID, and verifying contract;
- payment token has 6 decimals.

The command is read-only. It also prints BaseScan links for the three contracts. Open them and confirm the source and addresses.

## 6. Create the invitation

```sh
node skills/p2p-orders/scripts/pilot.mjs invite --deployment <pilot directory>/public/deployment.json --out <pilot directory>/public/invitation.txt
```

Share only:

1. the matching `p2p-orders` Skill package;
2. `public/deployment.json`;
3. `public/invitation.txt` (or the fingerprint separately, out of band).

Never share `deployer-wallet.json`, `evaluator-wallet.json`, `deployment.actions.sqlite`, participant wallets, state directories, or session logs.

## 7. Onboard the buyer and seller on two devices

Each participant, on their own device and in their own directory:

```sh
node "<skill>/scripts/pilot.mjs" join --deployment "<deployment.json>" --fingerprint "<fingerprint>" --role buyer|seller --out "<new participant directory>"
node "<skill>/scripts/pilot.mjs" doctor --config "<participant directory>/config.json" --state-dir "<participant directory>/state"
```

Each participant funds only their own new address with Base Sepolia ETH. A buyer then claims the valueless test payment asset once:

```sh
node "<skill>/scripts/pilot.mjs" claim --config "<participant directory>/config.json" --state-dir "<participant directory>/state"
```

Optional, for a Codex-hosted participant:

```sh
node "<skill>/scripts/pilot.mjs" bind-codex --participant "<participant directory>/participant.json" --session "<existing session UUID>" --codex "<absolute Codex executable>"
```

Run one read-only wake and confirm the same session resumed, the current order was read, and no funds moved.

## 8. First trade

Use a small, public task. The buyer's host agent should:

1. draft and validate the terms; confirm that no unresolved questions remain;
2. prepare and publish the order;
3. read the full order from the public manifest and ask the user to select a provider and confirm escrow;
4. approve the delivery only after reading the actual delivery and verifying its hash;
5. withdraw only the intended balance.

The seller's host agent should quote only within the user's authorization, deliver before the deadline, and withdraw only its own order credit. The user makes both payment decisions in the original conversation.

## 9. Failure drills

Run these before inviting more participants:

- Stop the RPC during a read; confirm the client reports failure and does not invent state.
- Lose the process after broadcast; recover the original `actionId` and confirm nothing is resent.
- Miss a review or delivery deadline; confirm the chain rules still apply while offline.
- Withdraw one order only; confirm other credits remain.
- Restore a backed-up state directory; confirm the journal and inbox still match the deployment and wallet.

## 10. Evidence and stop conditions

Save the deployment manifest, fingerprint, all transaction hashes, BaseScan links, participant evidence exports, and the first order ID. Keep raw wallets and session logs private.

Stop and do not continue if:

- the chain ID, deployment block hash, runtime code hash, or signing domain does not match the manifest;
- the deployer nonce changed outside the journal;
- an action remains `uncertain`;
- a participant's state directory belongs to another wallet or deployment;
- gas, RPC, or host permissions cannot be verified.

Do not use mainnet or real funds. The contracts are unaudited, immutable, and have no administrator.
