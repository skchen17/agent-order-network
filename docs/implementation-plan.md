## 本地验证

### v0.6接入与试点准备

已实现pilot命令：prepare生成新专用测试身份；join校验公开邀请并生成参与者自己的钱包；doctor提供可行动预检；deploy记录及恢复三笔固定合约部署；claim让每人从测试合约领取无价值支付资产；bind-codex绑定明确原会话及生成本地调度命令；status展示诊断和待办；export-evidence只导出白名单证据。

Base Sepolia 84532已加入显式testOnly白名单，主网仍禁用。公共配置校验构建运行时代码、部署区块、代码指纹及EIP-712签名域，至少3个区块确认；恢复和提醒游标遵循确认深度。公开清单不带部署者自选RPC令牌。每单默认上限2 TESTUSD。

真实模型试跑：新真实 Codex 会话完成独立接入、doctor、关注及恢复原会话读链，1 条事件确认，钱包 nonce、托管与 credits 均为 0。脱敏观察见[codex-live-trial.md](codex-live-trial.md)。同机夹具链，不是公共网或跨设备证明。

本轮npm test全量76/76通过，包含原流程、确认深度、主网拒绝、模拟84532部署恢复／代码核验、测试资产自助领取、适配器完成／事件ID校验、重复收件及证据隐私。模拟84532使用测试注入的EVM提供者，生产CLI不提供绕过网络校验的开关。真实模型试跑为显式运行的scripts/real-wake-trial.mjs，不在自动测试里悄悄调用模型。

公共网曾实测 RPC 和 chainId；部署尚缺测试 gas，未发送交易。试点步骤见[pilot-runbook.md](pilot-runbook.md)。未安装系统任务、未部署公共合约、未验证实际跨设备交易；按用户条件暂缓外部试点。

### v0.5试跑缺口修复

- 回执：所有Skill写入动作统一返回actionId及每步回执，公开载荷、代币授权、接单和清理均可追踪。返回前持久化；同一成功提案重复调用只读验证规范回执。
- 恢复：广播前保存意图，广播后保存哈希；recover_action只查询回执、nonce/calldata、当前订单与余额。未知广播保留本地写入锁；部分完成不自动继续付款。并发重复动作仅有一个写入者。
- 唤醒：参与者自己的持久待办、区块游标和截止提醒，由其已有调度器一次次运行wake命令，有事件才调宿主。成功持久接收后才确认事件，失败／超时重试，宿主按eventId去重。无项目方服务；未自动注册系统任务。
- 提款：新合约有每单应收额；withdrawOrders只提指定订单，withdrawAll原子检查金额及creditVersion。旧合约不升级，旧接口保留但Skill不使用。
- 环境：状态默认写当前工作目录的身份隔离目录，联网前检查可写性，schema说明运行参数；仍建议显式--state-dir以便定时任务和交互会话共享状态。

验证：本轮全量回归68/68通过，随后新增并发场景后恢复／提款／待办专项13/13通过（其中12项与全量重叠，不累加为81项）。包含真实子进程宿主的成功接收、失败和超时重试，以及广播后失联、仅授权后退出、回执失效和应收款范围变化。新版合约编译运行时代码12159字节；Skill结构校验通过。

独立分发包搬到仓库外临时目录，执行npm ci --omit=dev并检查14个工具描述及wake入口加载；运行时依赖审计报告0项漏洞，不代表合约审计。新版Codex CLI配置按官方文档及本机help核对，本轮未再次调用模型验证新唤醒配置。历史真实会话试跑见[codex-live-trial.md](codex-live-trial.md)，本轮接入方式见[恢复与唤醒](../skills/p2p-orders/references/recovery.md)。

环境：Windows PowerShell、Node.js 24、Hardhat 3、Solidity 0.8.37，编译目标 Cancun。所有依赖精确版本及完整依赖树记录在 package.json 和 package-lock.json。

编译产物不提交，npm run compile 重新生成。编译脚本检查错误和 EIP-170 运行时代码大小。通过 solc 的 JavaScript 接口编译，测试使用 Hardhat EVM 执行实际合约交易。

测试包括合约与任务模板、内联和公告传输、跨进程恢复、真实 HTTP 任务及独立复核、本地索引与访问限制。CI 式测试使用临时 HTTP fixture，不依赖外网站点；另通过 demo:live 验证了公开互联网站点的实际交易。供应方正常交付收到 1.5 单位本地测试支付资产。

编译工具 solc 的 tmp 依赖通过 npm overrides 固定为 0.2.7，以修正审计报告中的临时文件路径问题。安装后的依赖审计应以 npm audit 的实际输出为准。npm audit 不检查 Solidity 合约的经济或逻辑安全。

## 阶段一 跨进程原型

已交付：交易期间运行的本地链进程、部署清单、买卖方独立进程、链上签名报价公告、公开小数据内联传输、角色状态恢复和交易摘要导出。正常流程不依赖运营方中转、索引或文件服务器。

已验证：买方发布后重启仍使用原订单；供应方锁款后重启继续交付；只有一笔订单和一次报价；跨进程完成正常支付及两种异常退款。当前覆盖明确检查点恢复，尚未穷举断电、网络中断及交易处于待确认时的故障。

## 后续组件 独立接入（顺序服从上述优先级）

交付：MCP 服务器或 HTTP 工具服务、两个索引服务、第二种独立实现的客户端、持久预算和受限签名服务。

完成条件：订单可以通过另一个索引查到并继续操作；断线不会丢失截止提醒；两个框架无需共享运行时即可交易；模型读到恶意外部文本也不能扩大付款权限。

## 已有模板与真实任务测试

已完成：两个公开商品详情页的实际抓取、来源字段、买方独立重取、链上结果交付与本地测试款结算。连续接单、错误价格争议退款和索引恢复也有自动化测试。网络访问按域名、DNS 目的地址、大小、时限和重定向约束。

先邀请用户用日常语言描述调研、数据或其他真实需求，观察草稿是否忠实、澄清是否有效、候选理由是否易懂及确认能否完成。旧商品模板可辅助验证链下交付，但不再优先增加站点适配器。当前没有真实客户、复购或盈利数据，不能把练习站演示视为商业需求证明。

完成条件：买方有复用需求；至少两个供应方能够报价并交付；验收可解释；能够估算完整单笔成本。重点比较直接 API、脚本及人工采购的替代方案。

## 阶段四 受限资金试点

进入前完成测试网验证、独立合约审查、目标支付资产行为验证、费用测量、重组处理、监控告警及争议运营安排。重新评估供应方是否接受“仲裁超时退款买方”的固定规则。生产部署另行确定具体网络、合约版本及责任主体。

## 成本测量

一次正常跨进程原型订单通常包含创建、报价上链、资产授权、接受报价并锁款、公开结果公告、提交交付、确认／结算及提款；小数据可内联免去公告交易，授权和提款可以在多个订单间优化。内联及公告数据都增加链上费用。

当前不使用本地 EVM 的 gas 成本推算生产美元费用。需要在候选链测量交易大小、存储成本、确认时间和高峰费用，并加入模型、抓取、存储、RPC、人工争议成本后，再确定费率和最小订单金额。

## 第一轮评审应确认的事项

优先确认普通用户能否表达和读懂复杂条款、供应方能否从公开需求中找到合适订单、排序是否忠于自己的偏好，以及双方能否理解并确认交易。真实模型、发现完整性和实际成本应分别测量。评估方、默认超时风险、支付资产和具体测试网在真实资金前仍必须解决。
