# 公开商品网页采集试点

买方发布指定网址和交付条件，供应方独立访问网页并提取商品字段，买方再自行访问同一网址复核，确认后结算。当前已在公开互联网网页上完成该流程，资金使用本地 EVM 的测试支付资产。尚未进行公共测试网部署或真实资金交易。

## 可以运行的场景

目前支持两种静态 HTML 提取方式：

- books-to-scrape：公开抓取练习站的商品详情页。
- jsonld：指定域名中包含一个 JSON-LD Product 和明确 offer 的页面。

交付字段为商品名称、价格、币种、库存文字、原始网址、最终网址、抓取时间和页面 SHA-256 摘要。任务默认最多 10 个网址，全部页面都需要交付并通过检查。商品币种是数据字段，服务费用使用另外的测试支付资产。

Books to Scrape 明确用于抓取练习，站内价格为演示数据，不代表现实商品市场价格。[站点说明](https://books.toscrape.com/)

不支持登录页面、验证码、浏览器执行 JavaScript、任意选择器执行或凭订单文字执行系统命令。JSON-LD 格式和 offer 不受支持时会报错，不猜测缺失价格。

## 一键运行

项目根目录中执行：

```powershell
npm.cmd ci
npm.cmd run demo:live
```

这会临时启动本地链、部署订单和公开数据公告合约，生成两个独立开发钱包，完成抓取与交易后停止全部进程。默认任务为 examples/live-products.task.json，包含两个公开商品网址。

先仅检查抓取功能，不启动区块链：

```powershell
npm.cmd run fetch:products
```

抓取输出位于 .local-demo/live-products.json。完整交易结果位于 .local-demo/last-run.json 及其指向的 summary.json，包含实际商品字段和 independent-refetch 验收报告。互联网不可用或站点结构变化时命令可能失败，不会替换为固定价格假装成功。

## 使用自己的任务

任务文件格式：

```json
{
  "profile": "web.fetch.products.v1",
  "adapter": "jsonld",
  "urls": ["https://your-approved-shop.example/product"],
  "maxAgeSeconds": 600
}
```

1. 启动一次临时本地链：

```powershell
npm.cmd run local:network -- --out .local-demo/pilot-001 --port 8545
```

2. 在双方各自的 config.json 中配置 webPolicy.allowedHosts，仅加入实际允许访问的精确域名。该域名白名单属于本地操作者授权，订单不能扩大它。正式目标站点应先确认获取方式和访问条件。
3. 在独立终端启动买方：

```powershell
npm.cmd run agent:buyer -- --config .local-demo/pilot-001/buyer/config.json --task examples/live-products.task.json
```

4. 在另一个终端启动供应方：

```powershell
npm.cmd run agent:seller -- --config .local-demo/pilot-001/seller/config.json --serve
```

供应方在自己电脑上持续接单；不需要项目方运营接单服务器。默认开发配置只接受该次生成的买方地址及约定评估方。需要接受其他买方时，由供应方操作者调整 allowedBuyer，而不是相信订单内的授权声明。

连续发布另一笔任务时，为买方选择不同状态文件；同一钱包仍然一次只运行一个买方进程：

```powershell
npm.cmd run agent:buyer -- --config .local-demo/pilot-001/buyer/config.json --task examples/live-products.task.json --state .local-demo/pilot-001/buyer/job-002.json
```

供应方可以使用 --max-orders 2 在处理两笔订单后退出。任务与状态文件不能混用；同一状态文件用于恢复同一订单。停止本地链后所有测试链状态丢失，下次需要新的部署目录。

## 发现与筛选

每个供应方独立维护 orders.sqlite，本地保存已同步区块位置、区块哈希和订单状态。首次按支持的 taskType 分段读取历史事件，之后只处理新增区块；没有新区块时不逐笔重读历史订单。

SQL 先筛选待接、未过期、预算不低于报价、买方及评估方符合本地配置的订单，再按预算上限和接单截止时间选择最多 20 个候选。之后检查输入清单、域名、页面数、模板版本和验收方式。这里没有利润或供应方信誉预测模型；预算上限也不是已锁资金证明。

不支持的订单记入本地排除表，不会永久占据前 20 个候选位置。更改本地能力配置后重新考虑这些订单。选择并报价前，再读取一次链上状态；只有买方选定并锁款后才抓取网页。

断线后可根据游标补扫。保存的区块哈希改变或链回退时，索引会清空并重建；扫描途中失败不会推进同步位置。买方也保存当前订单的报价扫描游标，避免每轮从部署区块重扫报价。

筛选已使用 5000 条人工构造的本地索引记录验证精确金额比较和排除行为；这不是公共链吞吐或生产容量基准。

## 交付与验收

网址清单与结果首先尝试公开内联数据；超过 512 字节的 JSON 放入 OrderPayloads 公告合约，订单 URI 记录链 ID、公告合约地址和内容哈希。接收方只从配置允许的公告合约读取，并复核内容哈希。

公告上限 32 KiB，内容以事件形式公开，依赖 RPC 能提供相应历史日志。这样不需要文件服务器，但有额外写入、查询和历史数据可用性成本；不能用于私密或大量数据。以后需要按负载选择参与方传输或可替换存储。

买方检查网址覆盖、去重、抓取时间、字段和哈希，并重新访问每个页面比较商品字段。网页价格在两次访问之间变化，或买方访问失败，会导致验收异议；当前无法自动区分供应方错误与真实网站变化。

页面摘要与供应方时间声明本身不能证明来源真实；双方独立访问提供的是交叉检查，不是密码学真实性证明。双方使用相同解析器，也可能共享同类解析错误。真实付费试点仍需人工复核与明确的争议评估安排。

## 网络访问限制

只接受白名单中的标准 HTTPS 地址，禁止 URL 内凭据和片段。连接前检查 DNS 地址，拒绝私网、回环、链路本地等目标，并把通过检查的 DNS 地址固定用于实际连接，降低 DNS 重绑定风险。重定向重新校验，最多跟随 3 次。

默认每次抓取总期限 15 秒、响应上限 1 MiB、同一来源最小请求间隔 1 秒，不接受压缩响应。页面作为 HTML 解析，不执行网页脚本。

自动化测试可由本地操作者显式配置一个精确的回环 fixture origin；远端订单不能开启该例外。该例外不用于公开网站示例。

供应方抓取失败后记录 execution_failed，停止重复尝试，等待约定的未交付退款。买方仍需在验收期内在线检查；没有异议的提交在期满后可由供应方触发结算。

## 当前边界与下一步

- Agent 目前是独立自动化客户端，未接大模型或 MCP 工具服务。
- 角色钱包暂按单进程写入，没有生产会话密钥与多订单日预算服务。
- 本地订单索引可重建，但报价游标尚无公共链重组回滚设计。
- Node.js 24 中的内置 SQLite 仍会显示实验性接口警告；运行时版本与测试结果需一起维护。
- 支付仅支持本地开发链，公共测试网、确认深度、RPC 故障恢复及外部合约审查仍在后续阶段。

下一阶段先针对实际目标站点和使用者验证任务价值、数据变化规则及完整成本，再接公共测试网。当前不应直接改配置使用真实资金。
