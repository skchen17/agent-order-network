# 后续可选：小范围试点执行流程

本流程已准备但暂不开展；不是 v0.6 开发者预览版完成条件。当前入口见[开发者预览指南](developer-preview.md)。

本流程仅覆盖 Base Sepolia 测试网。Base 主网 8453 + USDC 使用[主网部署清单](mainnet-deployment-checklist.md)：默认关闭、要求外部签名器、未经审计，不得在 readiness gates 关闭前用于真实资金。

目标：陌生参与者使用自己的现成Agent和Skill，在不同设备上完成公开复杂需求、发现筛选、用户选定、交付及用户确认付款。项目方只做一次性构建、部署和试点组织，不运行账户、撮合、索引、文件、唤醒或发放测试支付币的服务器。

## 1. 发起者只做一次的工作

1. 构建并分发同一版本Skill：npm ci、npm run compile、npm run package:skill。包不含钱包、模型认证和运行记录，参与者各自安装运行时依赖。
2. 用Skill的pilot prepare生成新的专用部署身份；已有本轮身份继续使用原文件。doctor缺gas时停止，领取测试gas后再部署。
3. 运行pilot deploy。保存三笔交易回执、代码指纹及public/deployment.json；进程中断时保留目录，重新执行先恢复检查，不能换钱包或目录盲目重发。
4. 运行pilot verify --deployment public/deployment.json，核对链ID、部署区块、确认深度、运行时代码、支付资产和签名域；ready为true后再分发。verify不发送交易。
5. 运行pilot invite --deployment public/deployment.json --out public/invitation.txt，生成含指纹和接入步骤的公开邀请。已有邀请文件不会被覆盖。
6. 对照公共浏览器核对合约，分发公开清单、邀请文件、fingerprint及对应Skill包。私人RPC放在部署者自己的钱包配置；公开清单使用公共RPC，不带RPC令牌。
7. 部署后可关闭部署电脑。链上测试支付资产由参与者自己claim，不依赖发起者在线。评估方不是自动有人值守的服务；如试点未安排双方认可的人工评估方，明确采用原有争议超时退款规则。

完整命令、预期结果和异常停止条件见[部署清单](deployment-checklist.md)。[Agent接入命令](../skills/p2p-orders/references/pilot.md)供参与者自己的Agent执行，不要求参与者手写JSON或链上命令。

## 2. 每名参与者的接入

给参与者的日常语言邀请可直接使用[邀请模板](../examples/pilot-invitation.txt)。用户提供Skill、公开部署文件、邀请指纹和买方／供应方意向；自己的Agent负责以下工作：

1. 读取Skill及pilot参考，解释公开订单、费用单位、检查期和争议规则，核对邀请指纹。
2. join到一个全新目录，生成自己独有的钱包。绝不领取其他人的config.json、私钥或会话目录。
3. doctor检查本机执行环境、可写状态目录、测试网及合约代码。网络或构建不符时明确停止，不通过取消校验解决。
4. 缺gas时只展示自己的公开钱包地址和官方领取指引。外部水龙头的用户验证由该用户自己完成。买方有测试gas后调用claim，领取一次100 TESTUSD；它没有真实价值或美元兑付关系。
5. 用原宿主会话ID绑定唤醒，运行一次只读wake。检查同一会话确实恢复、读取订单、产生attention摘要及资金未动；然后将导出的命令接入自己允许的定时器。
6. 保留participant.json及同一state目录。自己的Agent可通过pilot status展示环境问题及最近待办，不把诊断错误原样甩给用户。

Codex CLI路径已做真实模型验证。其他API Agent可实现stdin事件接收适配器；Claude、dot或其他产品的安装与唤醒尚未验证，不在邀请中承诺即装即用。CLI日志不会自动成为桌面聊天弹窗；应由原宿主交互面呈现attention，或让用户在原会话询问待办。机器休眠／离线时不能执行定时任务，链上期限不暂停。

## 3. 第一关：两台设备、同一公开链、一笔完整交易

先只邀请一名买方和一名供应方，使用两台实际设备及各自独立的钱包、状态和宿主认证。双方只交换公开部署清单和指纹，通过RPC读写同一公共测试网；不开放任何一方电脑的本地节点端口，不共享localhost。

买方提出自己确有用途、可公开的小任务。例如：对一份公开源码生成中文检查报告，明确必须项、排除项、证据要求和交付格式。预算默认不超过2 TESTUSD；Agent忠实生成条款、解决歧义，用户知悉公开内容后发布。

供应方依据自己的能力阅读和筛选订单，解释匹配原因及不适合的条件，再在其用户授权内报价。买方选择供应方并明确同意锁款；供应方读取确认后的Funded状态才履约。交付后买方实际检查，用户再次确认付款，供应方只提取这一单应收款。消息、提醒、内容摘要和收件确认都不能替代这两次交易决定。

保存双方共享的订单ID、合约地址、所有交易哈希及浏览器链接；两端各自查到相同最终状态，供应方实际收到测试支付款。3个区块确认只是本轮测试网策略，不等于经济最终性保证。

通过条件：发起者不替任一参与者编写订单、挑选交易方、复制钱包或手动推进状态；双方能自行说明当前发生了什么、需要谁决定及何时到期。遇到问题记录在哪一步需要开发者介入，修复后再进入下一关。

## 4. 第二关：2—3名买方、3名供应方、约10笔真实需求

只开放公开的小型数字任务：文档整理、公开资料对照、源码检查等。暂不接个人资料、商业秘密、大文件、需注册垫付的任务及实物交付。参与者自选真实需求，避免发起者提前写好目标订单或给供应方指定订单ID。

加入能力相近、限制不同和预算不同的真实订单，观察Agent是否解释必须项、排除项和条件，而非仅按预算或标签选单。不承诺每单获得相同关注，记录每次检索覆盖范围、暂不可读项及候选排除原因。

逐笔记录：

| 观察项 | 记录内容 |
| --- | --- |
| 接入 | 从收到邀请到doctor就绪耗时；安装、领取gas和配置提醒分别需要几次人工帮助 |
| 表达 | 用户是否修改Agent条款，是否遗漏关键限制或制造用户没有承诺的条件 |
| 发现 | 候选数量、覆盖范围、漏掉／错选的订单及原因 |
| 成交 | 用户能否读懂报价、公开范围、检查期和风险并独立确认 |
| 履约 | 是否满足原需求，是否需要返工；不把自动验收作为前提 |
| 恢复 | 中断后是否重复动作、丢待办、错过期限或需要开发者介入 |
| 成本 | 实际链上gas、宿主推理及用户处理时间；不拿本地gas换算美元 |
| 复用意愿 | 买卖双方是否愿意再次使用，最想简化哪个步骤 |

## 5. 必测异常

- 关闭宿主后出现新订单／交付，重新运行检查，原会话接收且读取当前状态。
- RPC暂时不可达：预检清楚说明问题；恢复后补扫事件，不把失败当作未成交而重发。
- 交易已广播但输出丢失：用原actionId恢复，确认深度不足时继续保持未决。
- 用户尚未决定付款：提醒可以重复，余额与订单不因提醒而变化。
- 多订单应收款：只授权一单提款，其他余额保留；全部提款预览后的余额组成变化应拒绝旧提案。
- 交付有问题：先在期限内由用户决定是否争议；按双方已知规则验证测试款退款，记录评估方不可用的影响。

## 6. 收尾和准入判断

参与者自己的Agent用pilot export-evidence导出自愿共享的报告：匿名参与者／设备标识、公开地址、动作ID、交易回执及最后唤醒时间。默认不含私钥、RPC令牌、路径或模型对话。原始日志保留在参与者自己机器；不要索要整份工作目录。deviceId是自报标识，需结合试点实际观察确认跨设备，不能单凭ID宣称通过。

本轮准入目标：两台设备的完整交易确证；大部分参与者能独立接入及成交；每个中断案例不重复付款、不丢待办；双方能理解公开与超时规则。约10笔订单只用于暴露问题，不证明规模能力或市场需求。

所有测试款清算后，参与者可以停用自己的定时任务并关闭宿主；不删除仍有未决动作的状态记录。汇总共享报告与用户反馈，分别决定是否修接入体验、增加宿主支持或做更大规模发现测试。没有通过公共链和跨设备关卡前，不宣布公开网络已落地；本轮不开放真实资金。

官方网络资料：[连接Base](https://docs.base.org/get-started/connect-to-base)、[测试资金](https://docs.base.org/get-started/get-funds)。会话恢复依据：[OpenAI非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)。
