# 用户描述、匹配与确认交易（v0.3）

此文档为可选人工调试入口。v0.4 主路径是现有宿主 Agent 加 Skill，用户在原对话授权，不需要操作此客户端或安装本地模型。请优先阅读 [Agent Skill 接入](agent-skill.md)。

本版本将复杂订单表达和公开需求发现放在首位，自动验收为可选模板。主入口是本地命令行助手，不需要项目方账号或常驻应用服务。当前仅连接本地开发链，不支持真实资金。

## 亲自体验

安装 Node.js 24 或更高版本，在仓库根目录运行 npm.cmd ci。需要完整回放时运行 npm.cmd run demo:user：它用脚本模拟用户输入，启动临时链与两个独立 CLI，生成一份复杂需求，匹配、报价、锁款、提交模拟交付、人工确认并提款；同时验证取消发布、取消付款没有链上副作用。模拟确认只用于测试，不能用作真实交易授权。

手动操作需要三个终端：

```powershell
# 每次选新目录，保持该进程运行
npm.cmd run local:network -- --out .local-demo/user-001

# 需求方终端
npm.cmd run trade -- --config .local-demo/user-001/buyer/config.json

# 供应方终端
npm.cmd run trade -- --config .local-demo/user-001/seller/config.json
```

1. 需求方输入 new，用一句话描述需求，再确认／补充条款，保存草稿文件。示例为“帮我比较三个开源协议，中文 Markdown，必须附官方来源，不猜数据，不注册账号；来源不可访问时说明”。也可先用 examples/research-demand.json。
2. 需求方输入 publish，提供草稿路径，检查全部内容和资金规则，输入本次确认码。发布只创建需求，不锁货款。原始描述和全部条款都会公开，因此先删去不准备公开的信息。
3. 供应方输入 match，能力文件用 examples/research-capabilities.json，或交互填写自己的技能、领域、语言、格式、最低报价及所需时间。选择 relevance／deadline／rotation 排序，查看匹配理由、排除原因和复杂条件。
4. 供应方输入 quote，指定订单、报价和预计完成时间，核对全部条款并确认。报价不保留订单，只有被买方选中并看到 Funded 后才开始履约。
5. 需求方输入 fund，查看有效报价并选择序号。只有输入本次确认码才授权和锁款；可以选择较贵但更合适的报价，不默认选最低价。
6. 供应方履约后用 deliver 提交公开说明或小批量文字。最多 5000 字，当前不支持私密附件或自动执行任务指令。
7. 需求方用 review 查看交付，选择 approve 确认或 dispute 说明异议，再输入确认码。通过后供应方使用 withdraw 提款。

status 查看订单；cancel 取消尚未成交的需求；refund 在合约允许的超时后申请退款；finalize 在验收期满无异议时触发付款。每项写入操作都需单独确认。关闭终端不会取消订单或暂停链上期限。

## 复杂需求和澄清

demand.complex.v1 包含原始描述、标题、目标、领域、技能标签、必须项、交付物、排除范围、条件分支、人工验收约定、语言格式、预算及期限。模型生成的内容是建议；用户可以编辑、保留或清空。questions 非空或关键字段缺失时禁止发布。

预算使用本地 TESTUSD，最多六位小数，不将其他币种自动换算。招募窗口 1..168 小时；从发布起的总交付期限必须大于窗口且不超过 720 小时；检查期和仲裁期 1..168 小时。默认建议可以修改，发布预览展示实际时间戳。合约按这些期限执行，不自动理解文字中的条件分支、分期或附加付款要求。不要把自由文本条件视为智能合约已实现的支付功能。

修改已发布条款需要取消旧订单并新建草稿身份。重复发布同一草稿会提示原订单编号，不会创建第二笔订单。确认码绑定完整动作、网络、钱包、条款和当前状态，五分钟过期。模型或对方文字均无直接签名能力；确认码是本地交互控制，不是可公开托管的远程认证机制。

当前 ERC-20 授权和锁款是两笔交易，只授权选中报价的精确金额。锁款失败时尝试清零未用授权，并要求先查询状态；链或 RPC 不可用时撤销也可能失败，客户端会明确提示，不静默重新付款。

## 可选本地模型

默认无模型时为引导填写，保留原文并逐项确认，不宣称具备自然语言推理。只写草稿可运行 npm.cmd run trade，无需链和钱包。

已有本地 Ollama 及模型时：

```powershell
npm.cmd run trade -- --model <自己已安装的模型名>
# 也可以同时带 --config 进入完整交易
```

默认连接 http://127.0.0.1:11434，--model-origin 可指定其他本机 HTTP 端口。客户端仅向该本地端点发送需求和 JSON Schema，不发送私钥、钱包配置或交易工具，不自动下载模型，不在失败时切换云服务。模型选择与其是否自行调用外部服务由操作者控制。

接口采用 Ollama /api/chat 的 stream:false 和 format:JSON Schema，并在本地二次验证字段、类型和大小。官方参考：[Chat API](https://docs.ollama.com/api/chat)、[Structured Outputs](https://docs.ollama.com/capabilities/structured-outputs)。当前机器没有安装 Ollama，已验证模拟响应及拒绝非法输出；尚未验证真实模型的中文需求理解、速度、硬件需求或完整率。

## 公开发现与排序

每个客户端自己维护可重建 SQLite 索引。首次按 demand.complex.v1 扫描本部署的链上事件，之后同步新增区块；正文在读取时校验并缓存在本机。匹配按订单 ID 分页，检查所有当前可接单记录后再限制展示数量，不先按最高预算或历史成交截断。

当前为大小写归一化后的精确技能标签匹配，语言、格式、领域、最低预算和交付时间可显式过滤。复杂要求、排除范围、条件和验收约定全部列为待人工核对。系统不理解同义词，不提供语义或可履约性的保证。相关度排序为透明的标签规则；轮换按本地 seed 和订单 ID 计算固定顺序，不是防刷的公平抽签。更改本地偏好不需项目方许可。

返回匹配数、检查数、排除原因、不可读取记录及同步区块。存在不可读取项时不能认为结果完整。范围仅为当前部署的该版本订单，不是整个区块链所有交易。公开可检索不保证同等关注、流量或成交。

当前全量本地筛选为 O(N)，返回排除详情也占 O(N) 内存；是避免候选截断的正确性基础，不是百万订单吞吐承诺。后续应将结构化筛选和检索推进到本地索引，并允许参与者选择第三方可替换索引。

## 谁需要运行什么

项目方无需常驻撮合、目录、账号、文件或模型服务器。参与者运行自己的客户端和索引；选择本地模型者自己提供模型计算资源。开发链只在本地测试期间运行，停止后链状态丢失；不要删除旧状态后把相同部署当成新链。

未来公共链由其节点提供共识，参与者仍需可用 RPC、gas、钱包和及时查看提交／截止时间的设备；不能据此声称整个系统没有硬件或基础设施依赖。当前配置绑定 31337 开发链，尚未实现公共测试网确认策略。

现有不可升级合约仍采用“检查期满无异议可付款；仲裁超时退款买方”。这对双方有真实风险，尤其评估方失联对供应方不利。开发部署只生成离线评估地址，不提供人工仲裁服务。客户端没有自动值守、期限提醒、生产密钥管理或多进程钱包锁，同一钱包一次只运行一个客户端。本地开发配置和运行记录位于已忽略的 .local-demo，不应上传。
